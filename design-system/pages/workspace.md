# 설계 초안 작업실 (index.html) — MASTER에서 달라지는 점

`index.html`(로그인·홈·기능 명세서·ERD)에만 적용한다. 기존 산출물 뷰어(`viewer.html`)는 [MASTER.md](../MASTER.md)를 그대로 따른다.
기준은 사용자가 준 Runway 디자인 문서 + 3단 대시보드 시안 이미지이고, 토큰 값은 [src/app/index.css](../../src/app/index.css)가 기준이다.

## 방향

- Runway: 서체 하나, 그림자 없음, 장식 색 없음, 차가운 회색, 촘촘한 제목, 영문 대문자 소제목(450 굵기 + 자간).
- 시안 이미지: 왼쪽 사이드바(사용자·메뉴) / 가운데 큰 카드 목록 / 오른쪽 요약 카드의 3단, 밝은 회청색 바탕 위 흰 카드.
- 사진이 없는 업무 도구라 Runway의 '사진이 곧 화면'은 검은 구획(`--hero`) + 선으로 그린 테이블 장식(`SchemaArt`)으로 대신한다.

## Runway 문서와 다르게 한 것

| Runway 문서 | 여기 | 이유 |
| --- | --- | --- |
| abcNormal (Inter/DM Sans 대체) | Pretendard Variable | 한글 글리프. 기하학 산세리프에 450 굵기를 지원한다 |
| 서체 하나만 | 컬럼명·타입·ID에만 JetBrains Mono 추가 | 테이블·컬럼 이름은 고정폭이 읽기 쉽다 |
| 보조 글자 `#767d88` | `#656b75` | `#767d88`은 회청 바탕에서 3.6:1로 AA 미달. 같은 계열로 4.7:1 이상 |
| 11px 대문자 태그 | 최소 12px | 본문 최소 크기 규칙 |
| 줄간격 1.0~1.3 | 제목만 1.0~1.2, 본문 1.5 | 한글 본문은 1.5 미만에서 받침이 겹친다 |
| 어두운 화면 기본 | 밝은 화면 기본(시안), 어두운 화면은 OS 설정 | 시안이 밝은 화면. 어두운 화면 값은 Runway 색(#000, #1a1a1a, #27272a)을 쓴다 |
| 인터페이스에 색 없음 | 상태색(오류·경고·통과·정보)과 차트 두 계열색만 | 색만으로 뜻을 전하지 않도록 항상 글자·아이콘과 같이 쓴다 |

## 색

| 변수 | 밝음 | 어두움 | 용도 |
| --- | --- | --- | --- |
| `--canvas` | `#eef0f4` | `#000000` | 바탕 |
| `--card` | `#ffffff` | `#141416` | 카드 |
| `--sunken` | `#f5f6f8` | `#1c1c1f` | 카드 안 낮은 면, hover |
| `--fg` / `--fg-2` / `--fg-3` | `#0c0c0c` / `#404040` / `#656b75` | `#fff` / `#c9ccd1` / `#8f96a1` | 글자 3단계 |
| `--line` / `--line-strong` / `--control` | `#e1e4e9` / `#c9ccd1` / `#80868f` | `#27272a` / `#3a3a3f` / `#6b7079` | 구분선 / 강한 선 / 입력칸 테두리(3:1) |
| `--primary` | `#0c0c0c` | `#ffffff` | 주 버튼 (화면당 하나) |
| `--hero` | `#000000` | `#1a1a1a` | 검은 구획 (두 테마 모두 어둡게) |
| `--series-1` / `--series-2` | `#2a78d6` / `#c026a3` | `#3987e5` / `#e04fbd` | 차트 입력·출력 토큰 |

차트 색은 dataviz 검증 스크립트를 통과했다. 어두운 화면의 색약 구분(ΔE 7.5)은 '보조 표시가 있을 때만 허용' 구간이라 범례·막대 사이 2px 간격·'표로 보기'를 항상 둔다.

## 글자 (Tailwind 유틸리티)

`text-display` 48 · `text-headline` 36 · `text-title` 24 · `text-subtitle` 20 · `text-body` 16 · `text-label` 14 · `text-small` 13 · `text-micro` 12.
굵기는 400~600만 쓴다 (700 금지). 영문 소제목은 `eyebrow` 유틸리티. 한글은 `word-break: keep-all`이 전역에 걸려 있다.

## 모양·깊이

- 모서리: 버튼 4px(`rounded-sm`) · 입력/항목 6px(`rounded-md`) · 카드 8px(`rounded-lg`) · 강조 상자 16px(`rounded-xl`). 알약 모양 금지.
- 그림자 없음. 깊이는 바탕(`canvas`) → 카드(`card`) → 낮은 면(`sunken`)과 1px 선으로만.

## 배치

- 1280px 이상: 사이드바 256px + 가운데 + 오른쪽 340px. 오른쪽은 위에 붙어 따라온다.
- 1024~1280px: 오른쪽 카드가 가운데 아래로 내려간다.
- 1024px 미만: 사이드바는 상단 메뉴 버튼으로 여는 서랍(`<dialog>`).
- 페이지 전체 가로 스크롤 금지. 넓은 표·ERD는 자기 상자 안에서만 스크롤(상자에 `relative`를 줘서 sr-only 요소가 밖으로 새지 않게).

## 화면 구성

| 영역 | 내용 |
| --- | --- |
| 왼쪽 | 사용자 정보, 주 메뉴(홈·기능 명세서·ERD·상세 뷰어), My dashboard(프로젝트·편집 중·확정 수), 프로젝트 목록, 로그아웃(맨 아래 분리) |
| 가운데 | 단계 표시줄(① 기능 명세 → ② ERD → ③ 최종 산출물) + 각 단계 화면. 편집 단계는 초안 편집 탭과 확인 필요 탭(확인 질문·가정 규칙·검토 지적·자동 검사). 필수 항목을 모두 해결해야 확정, 확정하면 다음 단계 버튼. 기능 명세는 '저장'(웹 수정) / '내보내기 → ERD 만들기'(Agent에 넘김 → ERD 화면에 진행 상황 → 끝나면 새 ERD 버전), ERD는 '저장하고 새 버전 만들기'. 최종 산출물은 '최종 확정하기'와 최종 ERD. '산출물 보기'는 개요·요구사항·확인 질문·최종 ERD·DDL·추적·이슈·판단 기록, 최종 확정하면 제목 옆에 '최종 확정됨' |
| 오른쪽 | 진행 상황(기능 명세·ERD 확인 항목 눈금 막대, Agent 완료 조건), 버전별 토큰 사용량, 설계 버전(단계 화면은 그 단계 번호만: 기능 명세 v2 / ERD v2.k / 최종 v2.k.n, 제목은 연필 버튼으로 고침), 열린 검토 지적 |
